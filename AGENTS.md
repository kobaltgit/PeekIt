# PeekIt Project Instructions & Agent Protocols

## Автоматический протокол трекинга багов и задач (Bug Tracker Protocol)

Любой агент или ассистент, работающий в репозитории **PeekIt**, обязан строго следовать данному протоколу.

### 1. Триггер срабатывания (Когда активируется протокол)
Протокол активируется **автоматически** в любом из следующих случаев:
- Пользователь сообщает о баге, дефекте, сбое, зависании, визуальной ошибке или неожиданном поведении программы.
- Пользователь использует ключевые слова: «баг», «bug», «ошибка», «не работает», «сломалось», «зависает», «глючит», «дефект», «issue».
- В ходе тестирования, проверки типов (`npm run check`) или компиляции выявляется непредвиденная ошибка.

### 2. Обязательный алгоритм действий при обнаружении бага

1. **Немедленная регистрация в [`bugs/buglist.md`](file:///d:/Projects/active/PeekIt/bugs/buglist.md):**
   - Найти последний ID (`BUG-XXX`) и присвоить следующий свободный номер (например, `BUG-003`).
   - Добавить строку в сводную таблицу инцидентов.
   - Создать подраздел с подробным описанием:
     - **Симптомы / Воспроизведение.**
     - **Причина (Root Cause)** после первичной диагностики.
     - **Предлагаемое решение.**
     - **Ссылка на план решения.**

2. **Запись в оперативный журнал [`bugs/worklog.md`](file:///d:/Projects/active/PeekIt/bugs/worklog.md):**
   - Добавить блок с точной датой и временем:
     ```markdown
     #### [YYYY-MM-DD HH:MM] • [BUG-XXX] • [Диагностика]
     - **Цель:** Первичный анализ и локализация...
     - **Симптомы:** ...
     - **Статус:** Investigating / Open
     ```

3. **Ведение хронологии в реальном времени при исправлении:**
   - Каждое ключевое действие (правка файлов, пересборка, тестирование) должно сопровождаться краткой записью в [`bugs/worklog.md`](file:///d:/Projects/active/PeekIt/bugs/worklog.md).
   - Никаких скрытых правок без отражения в логе!

4. **Закрытие бага:**
   - После успешной верификации:
     - Изменить статус в [`bugs/buglist.md`](file:///d:/Projects/active/PeekIt/bugs/buglist.md) на `Resolved` (или `Verified`).
     - Добавить в [`bugs/worklog.md`](file:///d:/Projects/active/PeekIt/bugs/worklog.md) запись `[Завершено]` с указанием результатов тестирования.
     - Внести запись в таблицу «Хронология работы» в `buglist.md`.

5. **Синхронизация артефактов:**
   - Любые создаваемые артефакты планов (`implementation_plan.md`) или обзоров (`walkthrough.md`) должны копироваться в папку `bugs/` (например, `bugs/vX.X.X_plan.md`) и линковаться в `bugs/buglist.md`.

## Автоматический протокол трекинга нового функционала (Feature Tracker Protocol)

Любой агент или ассистент, работающий над добавлением новых возможностей в **PeekIt**, обязан строго следовать данному протоколу.

### 1. Триггер срабатывания
Протокол активируется **автоматически** в любом из следующих случаев:
- Пользователь просит добавить, разработать или внедрить новую возможность, функцию, интеграцию или модуль.
- Пользователь использует ключевые слова: «фича», «feature», «добавь», «внедри», «функционал», «новая возможность», «хочу чтобы», «давай сделаем».

### 2. Обязательный алгоритм действий при работе с функционалом

1. **Регистрация в [`features/featurelist.md`](file:///d:/Projects/active/PeekIt/features/featurelist.md):**
   - Найти последний ID (`FEAT-XXX`) и присвоить следующий свободный номер (например, `FEAT-002`).
   - Внести строку в сводную таблицу функций.
   - Описать архитектуру, требования и компоненты реализации.

2. **Запись в оперативный журнал [`features/worklog.md`](file:///d:/Projects/active/PeekIt/features/worklog.md):**
   - Добавить блок с точной датой и временем:
     ```markdown
     #### [YYYY-MM-DD HH:MM] • [FEAT-XXX] • [Проектирование / Разработка]
     - **Цель:** ...
     - **Выполненные действия:** ...
     - **Статус:** In Progress
     ```

3. **Ведение хронологии в реальном времени при разработке:**
   - Каждое ключевое изменение архитектуры, внедрение бэкенд-модулей, интерфейсных элементов или стилей фиксируется в [`features/worklog.md`](file:///d:/Projects/active/PeekIt/features/worklog.md).

4. **Закрытие и завершение фичи:**
   - После успешного прохождения проверок типов (`npm run check`) и компиляции (`cargo check`):
     - Изменить статус в [`features/featurelist.md`](file:///d:/Projects/active/PeekIt/features/featurelist.md) на `Completed`.
     - Добавить в [`features/worklog.md`](file:///d:/Projects/active/PeekIt/features/worklog.md) запись `[Завершено]`.
     - Внести запись в таблицу «Хронология работы» в `featurelist.md`.

5. **Синхронизация артефактов:**
   - Планы внедрения функций сохраняются в папку `features/` (например, `features/updater_plan.md`) и линкуются в `features/featurelist.md`.
