# План реализации: Исправление выхода (BUG-004), значки окна (FEAT-005) и запрет повторного запуска (FEAT-006)

## Ответы на вопросы и диагностика

1. **Почему пункт «Выход» перестал работать (ведь в прошлых версиях работал)?**
   - В версиях **v1.0.0 – v1.2.0** в меню системного трея при выборе «Выход» вызывался прямой системный выход: `std::process::exit(0);`.
   - В коммите `d4c96ac` (релиз **v1.3.0**) при переходе на новое API трей-меню вызов был заменён на библиотечный `app.exit(0);`.
   - Но в конце [`lib.rs`](file:///d:/Projects/active/PeekIt/src-tauri/src/lib.rs) на глобальном уровне установлен перехватчик:
     ```rust
     tauri::RunEvent::ExitRequested { api, .. } => {
         api.prevent_exit();
     }
     ```
     Этот обработчик предотвращает случайное закрытие приложения. Однако вызов `app.exit(0)` внутри генерирует событие `ExitRequested`, которое немедленно перехватывалось и отменялось! В результате приложение само блокировало собственную команду выхода.
   - **Решение:** Возвращаем надёжный прямой выход `std::process::exit(0);` при клике на пункт меню «Выход».

2. **По двойному клику разворачивание уже работает:**
   - Подтверждено: атрибут `data-tauri-drag-region` в Windows и WebView2 нативно поддерживает максимизацию / восстановление по двойному клику левой кнопкой мыши. Дополнительного JavaScript-кода для обработки двойного клика не требуется.
   - Фокусируемся на реализации **визуальных элементов управления**:
     - **Значок перетаскивания (Drag Handle)**: иконка захвата (6 точек `⋮⋮` или 4-позиционная стрелка `Move`), подсказка и курсор `grab / grabbing`.
     - **Значок максимизации / восстановления (Maximize / Restore)**: отдельная кнопка в панели действий с переключением иконок (`🗖` ➔ `🗗`) и подсказок в зависимости от текущего состояния окна.

3. **Запрет запуска нескольких копий приложения (Single Instance Mutex):**
   - Реализуем нативную защиту в [`main.rs`](file:///d:/Projects/active/PeekIt/src-tauri/src/main.rs) через именованный мьютекс Windows `Local\PeekIt_SingleInstance_Mutex`.
   - Если мьютекс уже занят (`ERROR_ALREADY_EXISTS`), новый процесс немедленно завершается (`std::process::exit(0)`), не создавая дублирующих значков в трее и не перехватывая системные хуки. Не требует тяжелых сторонних крейтов, используем уже подключенный крейт `windows`.

### 1. Бэкенд Rust (`src-tauri`)

#### [src-tauri/src/main.rs](file:///d:/Projects/active/PeekIt/src-tauri/src/main.rs)
- Добавить проверку единственного экземпляра:
  ```rust
  #[cfg(windows)]
  fn ensure_single_instance() -> Option<windows::Win32::Foundation::HANDLE> {
      use windows::core::w;
      use windows::Win32::Foundation::{GetLastError, ERROR_ALREADY_EXISTS};
      use windows::Win32::System::Threading::CreateMutexW;

      unsafe {
          let handle = CreateMutexW(None, true, w!("Local\\PeekIt_SingleInstance_Mutex")).ok()?;
          if GetLastError() == ERROR_ALREADY_EXISTS {
              peekit_lib::log_debug("Another instance of PeekIt is already running. Exiting.");
              std::process::exit(0);
          }
          Some(handle)
      }
  }
  ```
- В `main()` вызывать `let _mutex = ensure_single_instance();` перед инициализацией приложения.
